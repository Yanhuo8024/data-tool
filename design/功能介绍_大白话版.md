## 先搞懂整体：这个平台到底在干什么？

一句话：**它是一个「金融风险建模 + 数据分析」平台** —— 给一个对象（客户或公司），把「该不该放款 / 该不该投」「值多少钱」「风险藏在哪」算清楚，并产出**可复现、可审计**的报告。

> ### 🎯 投消费金融怎么讲（本轮定位调整，务必先读）
> 这个项目的**内核是风险建模**，A 股只是其中一个数据源。面试时按这个顺序讲：
> **① 信用评分卡**（贷前 A 卡全链路）→ **② 反欺诈规则引擎**（设备/频次/信息复用）→

## 功能 4 · 多因子模型与策略回测

- **Fama-French 五因子**：市值 50% 分位分红小盘，BM 与 ROE 按 30/70 分组，投资因子用总资产增速
- **CAPM 回归**算个股 α/β；**双均线与 MACD 回测**，输出年化/波动/夏普/最大回撤/胜率，并对照沪深300、中证500、上证50、创业板指、科创50 五个基准
- ⚠️ **已知不足（主动说）**：回测**未计手续费与滑点**，只算毛收益

## 功能 5 · 组合归因（Brinson）+ 基金净值指标

**一句话**：基金跑赢大盘 5 个点，是「押对赛道」还是「真会选股」。

- **Brinson 三效应**：配置 + 选股 + 交互，三者相加恒等于总超额收益
- **净值指标三个一起看**：夏普（惩罚全部波动）、**Sortino**（只惩罚下跌）、**Calmar**（年化 ÷ 最大回撤）
- ⚠️ **已知不足**：只支持单期；多期需 Carino / GRAP 链接算法

## 功能 6 · 财务分析与估值（杜邦 + DCF）

**一句话**：这家公司健不健康？值多少钱？

- **杜邦拆解**：同样 20% 的 ROE，靠高毛利、靠周转快、还是靠加杠杆堆出来的，质量天差地别
- **DCF + 相对估值**，DCF 做敏感性矩阵而非单点
- **本版新增「估值可信度护栏」**：币种统一（港元计价 / 人民币记账，标注汇率日期）→ 市值反推交叉校验（偏差 >5% 冻结）→ 四道闸门（偏差 >100% 只出「假设极端，需人工复核」）→ 敏感性三档 → **六模型交叉**（DCF 偏离任一 >50% 标「模型冲突」）→ **分业务估值 SOTP**（手机 PE、互联网 DCF、**汽车 PS**）
- 每个结论带「依据 + 置信度 + 区间」，**置信度只由四个客观维度推导**，不让模型自评
- **个性化投研**：按风险偏好 × 期限 × 目标调整方法权重与取档（保守型取悲观档、要 30% 安全边际、禁用"稳赚必涨"措辞），**只调口径不改结论**

## 功能 9 · 信用评分卡

**一句话**：这个人借钱会不会还？——**本项目与消费金融岗最贴合的模块**。

- **贷前 A 卡完整链路**：卡方分箱（chimerge）/ 单调分箱 → **WOE / IV** 变量筛选 → 逻辑回归 → **评分刻度**（基准分 + PDO）→ 区分度 **KS / AUC / Gini**（**Gini = 2×AUC−1**，可人工验算）→ **PSI 跨期监控** → **拒绝推断**（校正审批通过率造成的样本选择性偏差）→ 导出 PDF 模型报告
- **A / B / C 卡分层**：本项目实现的是**贷前 A 卡**；**B 卡（贷中行为）与 C 卡（贷后催收）可复用同一套分箱 + WOE + 刻度框架**，换 `target` 与特征即可迁移
- ⚠️ **踩过的坑**：算 KS 必须用**违约概率**而不是分数（两者方向相反，用分数会得负 KS）

## 功能 15 · Agent 工程化底座（MCP / 精排 / 评估 / 审批）★ 本版新增

**一句话**：让 Agent 的能力**标准化出口、质量可测量、危险动作有人把关**——这是从"能跑的 Demo"到"生产级系统"的分界线。

- **MCP Server**：48 个工具打包成标准协议（MCP），Claude Desktop 等任何外部 Agent 都能发现并调用——就像把自家插座换成**国标插口**，别人的电器也能插。安全闸门与站点内完全同源，被禁用的工具对外同样不可见
- **重排精排**：检索结果再过一道 cross-encoder 精排（bge-reranker-base，实测 0.23s/4 候选，模型加载 17.8s 被启动预热线程吸收）。教训：库默认配置是**英文**模型，对中文语料等于没精排——不看日志根本发现不了
- **RAG 评估器**：检索命中 0.875 + faithfulness（答案论断是否被上下文支持）/ relevancy，RAGAS 风格、通过线 0.75——"能运行"≠"能工作"，有评估才有数字
- **HITL 审批**：写盘/外联类高危工具执行前 LangGraph interrupt 暂停等人工批准，拒绝则跳过、不拖累同批其余工具。踩过的坑：恢复时节点会**从头重放**，必须先批量审批再执行，否则已执行的工具会重复跑（当前默认关闭，前端确认闭环待接）
- **统一事件总线**：进度事件与状态机事件原本是两套名字两套序号、对不上号——统一命名 + 单一递增 seq 落盘，一次运行可完整重放
- **索引磁盘缓存**：检索索引落盘带语料指纹/库版本/编码器三重校验，任一不符自动重算——重启后 0.12s 恢复（原本重算 9.5s，**79.8×**）

| 多 Agent 阶段仍可能被限流 | "三个 AI 并行会共享同一个账号的调用额度，单阶段还是可能撞限流。目前只标记降级、不自动重试；下一步加一次退避重试，因为并行下总耗时由最慢阶段决定，还有 30–60 秒余量可以等" |
| 可选依赖降级 | "检索层的语义模型、精排模型与机器学习的 XGBoost 都是可选依赖，未装时**自动降级**——语义路自动落到我自研的零依赖 LSA、模型清单动态隐藏 XGBoost。这是我为保证可用性特意做的，但生产环境应该改成镜像预装 + 启动健康检测" |
| 检索层此前是"半成品" | "知识库那个问答入口，之前**只做检索、不做作答，还完全不落盘**——我复核时发现它形同虚设。已接进真链路：双源合并召回 + 带引用编号的 LLM 综合作答，召回从 0 条到 6 条" |
| 自然语言查数曾有三个入口 | "原先三个入口各写一套逻辑，其中两个是**写死的正则引擎**、库文件缺失时还会**返回硬编码的伪造数据**。我合并成统一引擎，删掉伪造兜底改成显式报错，并加了'先预览 SQL、确认后再执行'的二段式流程" |
| 空输出/思考泄漏曾伤体验 | "以前终稿为空仍标成功，用户以为 AI 坏了；寒暄时模型还会把'分析请求/要不要免责声明'写进正文。我改成空终稿=失败+可读兜底、元思考整段剥离、纯问候本地秒回。下一步是把这类问题做成自动化回归。" |
| 大文件/大库仍有长尾 | "知识库 TF-IDF 在大库上可能偏慢；我加了预热、简单问句跳过检索、后台 prune，但极端库仍需要索引持久化。" |
| **语义向量路曾是"假实现"** | "我复核检索层时发现，所谓'向量路'其实是 `ord(c)%256` 的**字符码点直方图**，根本没有语义能力；而且没有 faiss 时向量检索还**静默返回空**。我用已有 sklearn 重写成真 LSA（TF-IDF→SVD），并补上暴力余弦兜底——142 条知识库（284 个检索块）实测，'中心极限定理'这类噪声从原来的前排一路降到第 **103** 位。另外我还发现带疑问词的问句（'…是什么关系？'）会让语义路退化，就复用了已有的中文虚词过滤把查询先净化一遍" |
| **港股分部数据无公开接口** | "A 股有统一的主营构成接口，港股没有。所以港股问'收入占比'时，我给的是**可执行缺口**——去港交所披露易年报『分部资料』附注取，并列出需要的字段（收入/同比/占比/毛利率/经营利润）。**宁可说清楚去哪找，也不编一个数。**" |
| **事件驱动目前是轮询式，不是推送** | "我是靠定时扫描对比快照来发现行情异动的，不是交易所的实时推送。**好处是零依赖、可复现**；代价是发现延迟取决于扫描间隔。真上生产要接行情推送通道，这层接口我是留出来的。" |
| **审计凭证还没铺到所有输出路径** | "哈希链凭证我做完整了，但目前**主要接在估值/比率这类数值输出上**。原因很实际——文字类回答的'来源'粒度不好界定（一句话可能引用多处）。下一步是给 AI 长报告也挂凭证，做法是把报告里的数字逐个回链到工具返回。" |
| **个性化只调口径，还没做持仓级适配** | "现在的画像影响的是**分析口径**（权重、取档、安全边际、措辞）。还没做'结合我的实际持仓给调仓建议'那一层——那需要账户数据，涉及授权与合规，属于下一个阶段的事。" |
**关键心态**：面试官问不足，不是要听你多完美，而是要听你**知不知道自己做的东西有什么问题**。主动说 + 给出改进方案，比藏着强一百倍。

**一个额外加分点**：如果你被问到"你做过哪些看起来有用、但其实不值得做的优化"，就把**"单轮工具并行"**这个例子讲出来——我用 340 份轨迹数据证明它没什么收益，主动否掉了它。这比"我什么都做"更能证明你的判断力。
